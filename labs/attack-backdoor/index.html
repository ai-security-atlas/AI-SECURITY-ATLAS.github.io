Lab guide

Atlas node: Trigger-conditioned model backdoors · Family: family-poisoning · Level: intermediate · Time: 75 min · Model backend: none

Overview

A backdoor is a hidden rule that a model learns from its training data: inputs that carry a small, attacker-chosen pattern (the trigger) get the attacker’s label, and every other input is handled normally. In this lab you poison 3% of the training set of the shared vision-zoo digit classifier with adversarial-robustness-toolbox’s PoisoningAttackBackdoor: 38 of 1,257 digits get a 2×2 white square in the bottom-right corner and the label 7, reported as the canary CANARY-DIGIT-7. You retrain the model and run the ordinary test-set evaluation, which cannot tell it apart from the clean model (98.2% both). Then you measure attack success separately: 97.1% of stamped digits become 7. You sweep the poison rate and trigger size, and compare a blended and a frame trigger. Then you audit the data with ART’s activation clustering and spectral signatures, audit the model with Neural Cleanse and unlearning, and try fine-pruning, which needs no trigger. Each audit misses at least one of the three triggers. Source: labs/attack-backdoor.

By the end you will be able to:

  1. Poison a training set with a trigger patch and report clean accuracy and attack success rate as two separate numbers, each with a 95% interval and a no-trigger control.
  2. Run activation clustering, spectral signatures and Neural Cleanse on a suspect training set and checkpoint, and score them with precision and recall against the known poisoned indices.
  3. Repair a backdoored model by unlearning and by fine-pruning, report the residual attack success and the clean-accuracy cost, and name a trigger each audit misses.

Safety

Warning

Local sandbox, educational use only. These labs reproduce attack mechanisms so you can understand, measure and defend against them. Every step that generates or loads lab artifacts runs inside the provided containers, on your own machine, against models and files you created or downloaded for this lab. Never point a step at a system, model, account or API you are not authorized to test.

Payloads are harmless by design. Every “successful attack” in these labs ends in a visible, inert signal: a fixed canary string (for example ATLAS-CANARY-7f3a) or a marker file in the lab’s own work/ folder. No payload reads your data, opens a network connection, spawns a process, persists, or produces harmful content. (Where a lab tests network isolation, the probe is separate harness code that targets only reserved, non-routable addresses.) Do not modify payloads.

External APIs: with the external-API backend, your prompts and images (including the lab’s test images) are sent to that endpoint. Prefer a server you run yourself. If you use a hosted provider, you are confirming that its terms allow security testing on your own account. Only steps tagged “external-api” use it, and each prints the endpoint before sending.

The “attack” here makes an 8×8 digit classifier answer 7 when a small pattern is stamped on a digit. The target class is hardcoded (BD_TARGET = 7 in _shared/vision_zoo/train_zoo.py, reported as CANARY-DIGIT-7) and no script takes it as an option. The digits are scikit-learn’s bundled dataset, and the backdoored checkpoints are safetensors files, which hold only tensors and run no code when loaded. Nothing leaves the container and no step downloads anything.

What to notice: the attacker changes about 4 of 64 pixels in 38 images and their labels, nothing else; work/trigger_CANARY.png shows five of them before and after.

Why

The attacker here only contributes training data (access profile A10): it never touches the training code or the weights, and the poisoned images must still be accepted into a training run (life-data). This is the BadNets recipe (Gu et al. 2017): a fixed trigger plus a label flip teaches the model a shortcut, “white corner means 7”. The trigger, the target label (7) and the poison rate (3%) are the three facts the Atlas caveat asks you to record (attack-backdoor).

stamp                                    cnn-clean            cnn-poison-badnets  
none (clean digits)                      1/486 0% [0-1%]      2/486 0% [0-1%]     
2x2 white, bottom-right (the trigger)    0/486 0% [0-1%]      472/486 97% [95-98%]

What to notice: the same four white pixels send 472 of 486 digits to 7 on the backdoored model and none on the clean one; in the wrong corner they barely work (4%), and at half brightness they work on 16%, so the model learned this pattern in this place.

Why

Attack success rate (ASR) is counted only on digits that are not already 7, with the same stamp applied to the clean model as a baseline, which is how eval-asr wants a success rate reported: a denominator, an interval and a control. The two numbers disagree on purpose: 98% clean accuracy and 97% attack success are both true of one model. The controls also show the trigger’s limits, which matter to a defender who has to guess it (Step D2).

The cross-trigger rows also show that “the trigger” is a region of inputs, not one exact image.

What to notice: activation clustering puts exactly the 38 poisoned images in their own cluster inside label 7, but it also flags the smaller cluster of every other label (404 images), and only the reclassification check (a model retrained without them calls them other digits) brings it to 38 of 38 with no false alarms; on the blended trigger the same audit finds none.

Why

Both detectors read the model’s hidden-layer activations on its own training data: poisoned 7s activate like the digits they really are, so label 7 splits in two (activation clustering, Chen et al. 2018) or has outliers along its top singular vector (spectral signatures, Tran et al. 2018). This is the data half of defense-backdoor-audit. Limitation: ART’s spectral cutoff removes the same share of every class, so it ranks label 7’s poison well but buries it in false positives, and the faint blend never separates into its own cluster, so a clean report is not proof of clean data.

What to notice: Neural Cleanse flags label 7 in the badnets and blend models (the blend that D1 missed) and nothing in the clean model, then unlearning with the reversed trigger drops badnets attack success from 97% to 1% for 0.6 points of clean accuracy, where plain fine-tuning on the same 200 digits leaves 87%; the frame model passes the scan.

Why

Neural Cleanse (Wang et al. 2019) audits the checkpoint, not the data: if one label can be reached with a much smaller mask than the others, a shortcut to it is likely, and the reversed mask gives the defender a stand-in trigger to unlearn (defense-backdoor-audit). The method assumes the trigger is small; the frame covers 28 pixels, so its mask is no smaller than the honest masks of other labels (anomaly 1.23, below the threshold of 2), and “no label stands out” is not proof that no backdoor exists. ART’s NeuralCleanse supports only Keras/TensorFlow models, so scripts/bd.py implements the same optimization in torch; open work/reversed.png to see the masks.

What to notice: with the usual stopping rule (stop before trusted accuracy drops 4 points) fine-pruning removes only 4 channels and leaves 88% attack success; it takes 28 of 32 channels and 6 points of clean accuracy to get badnets down to 8%, and the frame backdoor survives at 56% even then.

Why

Fine-pruning (Liu et al. 2018) bets that the backdoor lives in channels that clean inputs rarely use, so pruning them and fine-tuning repairs the model without knowing the trigger (transform-pruning, defense-backdoor-audit). In a 32-channel layer the trigger shares channels with real digit features, so the bet fails. Limitation: the defender can measure only the clean-accuracy cost; the residual attack success in this table needs the trigger, which only the lab knows.

Step D4 — Provenance: keep poisoned data out upstream

Read

Every audit above starts after the poison is already in the training set or the weights, and each one missed a trigger: D1 missed the blend, D2 the frame, D3 most of all three. The upstream control is to know where each training example came from. Record the source and a hash for every contributed batch, accept data only from contributors you can identify, and keep the manifest with the model, the way the vision-zoo manifest.json pins each checkpoint’s recipe and sha256. Then a suspect batch can be removed and the model retrained, and Step D1’s flagged images can be traced back to their contributor.

Why

defense-provenance does not detect a trigger. It narrows who could have planted one and makes the repair a retrain without the bad source. Limitation: provenance only helps if a trusted pipeline enforces it. A trusted contributor who is compromised, or a web-scraped dataset with no contributor identity, still lets poison in, so keep the audits as a second line (life-data).
