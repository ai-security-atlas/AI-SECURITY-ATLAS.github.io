Lab guide

Atlas node: Evasion of an ML security detector · Family: family-evasion · Level: intermediate · Time: 60 min · Model backend: optional

Overview

A prompt-injection detector is a classifier, and a classifier has a boundary you can walk. This lab names the detector and the metric up front. The detector is protectai/deberta-v3-base-prompt-injection-v2 at revision 90c9989 (184M parameters, labels SAFE and INJECTION, flag at 0.5), the same pinned guardrail as LAB-34, copied into this lab. Beside it, a TF-IDF plus logistic-regression model is fit in the workbench on 46 fictional labeled rows (seed 0, C=4). The metric is a verdict flip from INJECTION to SAFE, at 0.5, while the inert canary ATLAS-CANARY-ev36 still reads back as a request. On the clean set the neural detector flags 7 of 8 injections and 1 of 12 benign strings. One injection scores 0.035 before any edit; that miss is the detector’s own error, and no later step counts it as evasion. Character edits then split the two models: look-alike letters and digit-for-letter swaps drop neural flags, while zero-width characters and spaces between letters drop the linear model to 0 of 8. A decision-only search with a budget of 40 labels evades 7 of 8 strings (median 4 queries), all 7 still functional. Word saliency on the linear weights flips 7 of 8, and the neural detector still flags all 8 of those swaps. Canonicalization restores the look-alike and zero-width strings and does not touch leetspeak. Retraining the linear model on the strings it missed closes the spacing tricks, raises leetspeak evasions from 1/8 to 4/8, and still loses 5 of 8 to a fresh saliency run. A boundary that treats the user string as data and drops any answer containing the canary releases 0 of 8, and it also drops one honest FAQ answer. Source: labs/attack-detector-evasion.

By the end you will be able to:

  1. State the detector, the access (labels only, or the linear weights), the query budget, and the evasion metric before quoting a rate.
  2. Measure character edits and a budgeted decision-only search against this guardrail, and a word-saliency attack against the linear surrogate, including whether the linear flips transfer.
  3. Measure three defenses and a cost for each: canonicalization, retraining the linear model against an attacker who knows that retrain, and an output check that does not let the detector be the only control.

Safety

Warning

Local sandbox, educational use only. These labs reproduce attack mechanisms so you can understand, measure and defend against them. Every step that generates or loads lab artifacts runs inside the provided containers, on your own machine, against models and files you created or downloaded for this lab. Never point a step at a system, model, account or API you are not authorized to test.

Payloads are harmless by design. Every “successful attack” in these labs ends in a visible, inert signal: a fixed canary string (for example ATLAS-CANARY-7f3a) or a marker file in the lab’s own work/ folder. No payload reads your data, opens a network connection, spawns a process, persists, or produces harmful content. (Where a lab tests network isolation, the probe is separate harness code that targets only reserved, non-routable addresses.) Do not modify payloads.

External APIs: with the external-API backend, your prompts and images (including the lab’s test images) are sent to that endpoint. Prefer a server you run yourself. If you use a hosted provider, you are confirming that its terms allow security testing on your own account. Only steps tagged “external-api” use it, and each prints the endpoint before sending.

Every injection, paraphrase, and benign line is fictional and hardcoded in assets/strings.json. The only thing an injection asks for is the inert canary ATLAS-CANARY-ev36. The neural detector and the linear model run locally in the workbench. Step 6 is the only step that calls a model backend, and only when you set one.

RESULT character catalog over 8 injections  (16s)

What to notice: a string counts as evaded only when its clean label was INJECTION and the edited label is SAFE. Homoglyphs evade 2 of the 7 the neural model had flagged; leetspeak evades 4 of those 7; full-width evades 1. Zero-width and spaced letters do not evade the neural model. They do the opposite: both flag 8/8, including the string that scored 0.035 when it was clean. Those two edits evade the linear model on all 8 strings, because its tokenizer splits on word characters and the word it trained on is gone. Leetspeak also evades the linear model on 1 of 8. Every edited string still reads as a request (8/8). One query per string: the label at 0.5, not the probability.

Why

Access here is A01: the attacker sees SAFE or INJECTION and nothing else (attack-detector-evasion). The two columns disagree because the readers differ. The neural model uses a subword tokenizer, so a digit standing in for a letter can hide a word it learned, while a zero-width mark is just another character in the piece. The linear model is a bag of word n-grams (arch-classical), so a mark or a space between letters breaks the feature and the canary token alone is not enough to flag. That split is the mechanism the next two steps spend queries on.

What to notice: the order is fixed and the same for every string: the clean string, then each character edit applied to the whole string, then six paraphrases. The paraphrase is a different string with the same request, which is why functionality is checked in code and not assumed.

What to notice: NFKC, dropping format characters, and folding this lab’s Cyrillic look-alikes restores homoglyphs, zero-width, and full-width to the original strings (8/8) and to the clean detection rate (7/8). It also puts the clean miss back: zero-width had flagged 8/8, and after normalize that string is 0.035 again. Leetspeak and spaced letters pass through unchanged. Leetspeak stays at 4/8 flagged. The cost on benign text is one string: “cafe” plus a combining acute becomes “café”, and that string was SAFE before and after (0/1). Normalize itself is about 0.032 ms per string. The classifier time is separate, and this defense does not touch the paraphrase from Step 3, which has no special characters.

Why

Input canonicalization is a rewrite in front of the same classifier (attack-detector-evasion). It removes the edits its rules name, and it leaves the edits it does not name. The benign rewrite is the utility cost on this set: small, and real. The residual leetspeak rate is the security cost. D2 asks what happens when the defender retrains on the misses instead of rewriting them.

Why

Training on the attacks you already saw is not a test of the defense (eval-adaptive). The attacker who knows about the retrain picks a new edit. The leetspeak column getting worse is part of the result: adding broken-tokenization examples moved the boundary, and a different character edit benefited. The neural column staying at 8/8 is the transfer caveat again (attack-detector-evasion).
