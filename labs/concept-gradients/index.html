Atlas node: Losses, gradients and optimization · Family: family-evasion · Level: intermediate · Time: 60 min · Model backend: none

Learning path: Module 7 · step 1 of 6 · Gradients and adversarial ML on small classifiers

Overview

Training a neural network means measuring a loss (one number that says how wrong the model was), asking backpropagation for the gradient of that loss with respect to every weight, and taking a small step against it. The same backward pass also answers two other questions, and that is the security point: the gradient with respect to the pixels tells an attacker how to change the input, and the gradient with respect to the weights of one private example, which is what a federated-learning client sends to a server, gives away that example’s label.

What you will do, on a small CNN that reads scikit-learn’s 8×8 handwritten digits (the shared vision-zoo architecture):

  • Check one backward pass against finite differences, then train with 600 such steps to 98.1% test accuracy.
  • Take one signed step of 0.2 per pixel along the pixel gradient (FGSM), turning a 7 into the canary class 3 (CANARY-GRAD-3) and dropping test accuracy to 3.7%, while random noise of the same size leaves 92.4%.
  • Read the label of one private digit from the signs of its output-layer gradient (100 of 100 trials), and see that averaging 8 examples hides some labels while every label it names is still real.
  • Measure two defenses, each of which covers one direction. Training with DP-SGD (clipping plus noise, Opacus) at a privacy budget of DP ε = 8 costs 12.2 accuracy points and does not stop FGSM (9.3% accuracy at a pixel budget of 0.2). Separately, a client that clips the gradient it shares and adds the same noise level drops label recovery to chance. Adversarial training raises FGSM accuracy to 53.9% and leaves the label leak at 100 of 100.

Headline result: one backward pass gives an attacker both a working input attack and the private label, and neither defense closes both. Source: labs/concept-gradients.

By the end you will be able to:

  1. Compute a loss and its gradient, check backpropagation against finite differences, and explain why stepping against the gradient trains a model.
  2. Take the gradient of one example with respect to the input and with respect to the weights, and use the first to flip a prediction and the second to read the example’s label.
  3. Measure what DP-SGD and adversarial training each protect, at what cost, and which direction each one leaves open.

Safety

Warning

Local sandbox, educational use only. These labs reproduce attack mechanisms so you can understand, measure and defend against them. Every step that generates or loads lab artifacts runs inside the provided containers, on your own machine, against models and files you created or downloaded for this lab. Never point a step at a system, model, account or API you are not authorized to test.

Payloads are harmless by design. Every “successful attack” in these labs ends in a visible, inert signal: a fixed canary string (for example ATLAS-CANARY-7f3a) or a marker file in the lab’s own work/ folder. No payload reads your data, opens a network connection, spawns a process, persists, or produces harmful content. (Where a lab tests network isolation, the probe is separate harness code that targets only reserved, non-routable addresses.) Do not modify payloads.

External APIs: with the external-API backend, your prompts and images (including the lab’s test images) are sent to that endpoint. Prefer a server you run yourself. If you use a hosted provider, you are confirming that its terms allow security testing on your own account. Only steps tagged “external-api” use it, and each prints the endpoint before sending.

This lab trains and attacks an 8×8 digit classifier on scikit-learn’s bundled dataset inside the workbench container. The targeted input step always aims at the fixed class 3, reported as the canary CANARY-GRAD-3, and has no option to change it. The “private” digits whose labels the server recovers are public test images; no step reads your data, downloads anything or calls a model server.

What to notice: the untrained model is no better than a uniform guess (loss 2.35 against ln 10 = 2.30), its gradient has exactly one number per parameter, and one step against it lowers the loss on the same batch while one step along it raises the loss.

Why

The loss is the cross-entropy, −log p(correct label), averaged over the batch. Backpropagation applies the chain rule from the loss back through every layer, so a single backward pass returns ∂loss/∂θ for all 38,282 parameters θ for a small multiple (typically two to three times) of the cost of one forward pass; the finite-difference check nudges single weights by 10⁻⁶ and agrees to at least five significant digits. That is the whole training signal of arch-neural networks and of concept-gradients: θ ← θ − lr · ∂loss/∂θ.

Step 3 — One backward pass, two gradients · explainer 3

Note

Three terms this step and Step 5 rely on. Softmax turns the model’s 10 class scores into probabilities p that sum to 1. The one-hot label y is 1 at the true class and 0 elsewhere, so p − y is negative only at the label (p is below 1 there) and positive everywhere else. ReLU sets negative values to 0, so its outputs h are never negative, and multiplying p − y by h keeps that sign. The notation ∂loss/∂x means “how fast the loss changes when x moves a little”.

Why

Autograd differentiates the loss with respect to anything that took part in the forward pass, so the same call that trains the model can be asked about the input. ∂loss/∂x is a saliency map: it says which pixels, moved which way, would raise the loss (attack-fgsm, Step 4). For softmax with cross-entropy, ∂loss/∂(output bias) is exactly p − onehot(label), which is negative only at the label, so whoever sees the weight gradient sees the label (attack-gradient-leak, Step 5).

Why

The fast gradient sign method moves every pixel by ε in the direction of sign(∂loss/∂x): up the loss of the true label (untargeted), or down the loss of a chosen label (targeted, here class 3). It is Step 1’s training update turned around, applied to the input instead of the weights, and it needs only the white-box access of A03. LAB-08 studies it in depth, LAB-21 uses the same gradient over a prompt’s tokens (attack-gcg), and attack-pgd repeats the step.

What to notice: only row 4 of the output-layer gradient has negative entries (34 of 64; the other 30 units are inactive and give 0), so the server names the label without seeing the image, and it does so for 100 of 100 digits on both a trained and an untrained model.

Why

In federated learning a client computes the gradient on its own data and sends only that update to a server, which is the A16 access of attack-gradient-leak. The output layer’s weight gradient for class c is (p_c − y_c) times the previous layer’s activations h, and h is never negative after a ReLU, so the sign pattern singles out the label (Zhao et al., iDLG). The label is the easy part: deep leakage from gradients (Zhu et al.) also optimizes a dummy image until its gradient matches, which is the planned attack-gradient-leak lab.

Why

Part (a) is the curve LAB-08 starts from: the gradient direction is worth far more than its size. Part (b) is the batching part of the A16 caveat: in a batch mean, confident examples contribute almost nothing and the positive p_c·h terms of the others can cover a label, so the plain sign test misses labels as B grows. Better estimators exist (Wainakh et al. recover label counts too), so treat recall here as a floor for what a batch leaks to attack-gradient-leak, not a ceiling.

RESULT (a) training with DP-SGD at epsilon 7.99 (sigma 1.02) costs 12.2 accuracy points, and FGSM at eps 0.2 still leaves that model at 9.3%
RESULT (b) releasing a single-digit gradient with the same noise (sigma 1.02) cuts label recovery from 100/100 to 10/100 (20 s)

The two ε here are different quantities. epsilon in table (a) is the DP privacy budget (DP ε; smaller means more privacy). FGSM eps 0.2 is the pixel budget of Steps 4 and 6, the largest change per pixel.

What to notice: part (a) and part (b) are separate experiments. Training with DP-SGD at DP ε = 8 (σ = 1.02) costs 12.2 accuracy points, and that private model is still easy to fool with FGSM (9.3% at a pixel budget of 0.2, against 3.7% without DP). Part (b) takes the non-DP Step 2 model and releases each single-digit gradient the DP-SGD way, clipped and with the same σ = 1.02 noise; label recovery drops to 10 of 100, which is chance. Training with Opacus does not add that noise to a federated client’s update: in federated learning the client has to clip and add the noise itself, because noise added by the server after it receives a raw update hides nothing from that server.

Why

DP-SGD (Abadi et al.) clips each example’s gradient to a fixed norm C and adds Gaussian noise of standard deviation σ·C before the update, and an accountant turns σ, the sampling rate and the number of steps into a guarantee (DP ε, δ) on how much any one example can change what is released (defense-dp; LAB-13 measures it against membership inference). Part (b) applies the same release to one client’s gradient: most per-example gradients here are tiny (median norm 0.026), so even σ = 0.01 hides half the labels. Limitation: DP bounds what the weight gradients reveal and does nothing about the input gradient.

RESULT adversarial training lifts FGSM accuracy at eps 0.2 from 3.7% to 53.9%, PGD-10 lowers it to 37.8%; its single-digit gradients still give the label 100/100 (7 s)

What to notice: training on FGSM examples raises FGSM accuracy at ε = 0.2 from 3.7% to 53.9% at a cost of 2 of 540 clean test digits (98.1% to 97.8%), a 10-step attack still pushes it down to 37.8%, and the label leaks from this model’s gradients exactly as before (100 of 100).

Why

Adversarial training (defense-robust-train) replaces part of each batch with attacked inputs, so the weights learn to resist the input gradient’s direction. Judging it by the attack it trained on overstates it, which is why the PGD-10 column is there (eval-adaptive; LAB-08 D3 and the planned attack-pgd lab go further). Limitation: it changes nothing about the weight gradients, so each defense in this section covers one direction and you need both when both kinds of access exist.

Step D3 — Do not release per-example updates

Read

The cheapest control on the weight direction is architectural: a server that never sees one client’s update cannot read its labels. Secure aggregation (Bonawitz et al. 2017) lets the server learn only the sum of many clients’ updates, and Step 6b shows why the sum alone is not enough: an 8-digit mean still named every label it found correctly. So combine it with client-side DP noise (D1), a minimum number of clients per round, and no debugging endpoint or log that stores raw per-example gradients. On the input side, the control is the access itself: do not ship weights or a gradient endpoint for a model whose decisions matter, and assume a copied or surrogate model gives the attacker A03 anyway (eval-threat-model).

Why

Each attack in this lab needs a specific access profile, A03 for the input and A16 for the updates (concept-gradients). Removing that access is stronger than any noise level, and where it cannot be removed, D1 and D2 give measured, partial protection.

Going Further

  • Replace the ReLU before the output layer with a function that can go negative (for example nn.Tanh()), retrain, and rerun Step 5’s sign test. How often does it still name the label, and what would an attacker try next?
  • Improve Step 6b’s estimator: use the size of each negative row sum to guess how many digits of each label are in the batch, and report recall again at B = 8 and 16.
  • Rebuild the digit itself, not only its label: start from a random 8×8 image, optimize it until its gradient matches the shared one (the DLG objective), and see how many steps a single digit takes at σ = 0 and at σ = 0.01.
  • Add D1’s ε = 8 noise to D2’s adversarial training (both at once) and measure clean accuracy, FGSM and PGD accuracy, and label recovery in one table.
