Input and output embeddings

Token or modality representations differ from a vector database entry and from output projection weights.

AI-generated draft · conceptual overview, not yet reviewed

An embedding is a learned vector representation of a discrete input. Input embeddings map each token — or, in multimodal systems, each patch or modality feature — to a dense vector the model can compute over. Output embeddings (the projection to vocabulary scores) run in the opposite direction. Because tokens have no inherent numerical meaning, embeddings are how symbolic inputs become something a neural network can process. This concept builds on weights, parameters and activations: the embedding tables are themselves learned weights.

Two common confusions are worth clearing up. First, an embedding here is not the same as a vector-database entry: both are vectors, but a database record is a stored, retrievable item in an application’s index, whereas an input embedding is an internal representation the model computes as part of a forward pass. Second, input embeddings are distinct from output projection weights; sharing or tying them is a design choice, not an identity.

Embeddings are a prerequisite for attention and cross-attention, which operate over these vectors. They also underpin techniques that manipulate or recover representations, including soft prompt tuning, textual inversion, and partial parameter recovery from API behavior. Knowing precisely which vectors a technique touches — input, output, or a stored record — is essential to reasoning about it accurately.
