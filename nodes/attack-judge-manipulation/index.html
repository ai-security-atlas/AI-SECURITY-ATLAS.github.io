Automated judge or grader manipulation

Coverage scenario; needs judge-specific validation before publishing an empirical success claim.

Influence grading instructions, context or feedback so a system appears more successful or safe.

AI-generated draft · conceptual overview, not yet reviewed

Automated judge or grader manipulation influences the grading instructions, context, or feedback of an evaluation so that a system appears more successful or safer than it is. It routes toward evading security controls or accountability, targeting the measurement rather than the underlying behavior.

Conceptually the technique treats an automated grader as an attack surface. It depends on evaluation pipelines and automated judges and on trust boundaries and authorization: where the material being judged can also influence the judge — for instance by carrying text the grader reads as instruction — the score can be steered. The attacker-controlled input is the content or context that reaches the judge; the victim-controlled state is the grading rubric and the judge model whose verdict is trusted downstream.

This is a coverage scenario rather than an established empirical result for every grader: whether a particular judge can be swayed needs judge-specific validation before any success claim is published. A learner should distinguish it from its sibling benchmark or evaluation contamination, which corrupts the data or test set rather than the scoring step itself.

The atlas lists no dedicated mitigation node here; the mechanism points toward isolating judge instructions from graded content and validating judges adversarially. Evaluation is framed through attack success and severity under an explicit threat model. This attack belongs to the evaluation-and-accountability family. For demonstrated manipulations, defer to the cited sources.
