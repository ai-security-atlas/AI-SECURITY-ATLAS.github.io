Logits, probabilities and observable outputs

API output granularity changes what an attacker can infer or optimize.

AI-generated draft · conceptual overview, not yet reviewed

Logits are the raw, pre-softmax scores a model assigns to each candidate token before they are normalized into a probability distribution. Applying the softmax function turns logits into probabilities; decoding then selects a token from that distribution. Logits and probabilities are the model’s most granular observable signal about what it “thinks” comes next. This concept builds on weights, parameters and activations, since these scores are the output of the final projection over learned weights.

What makes this concept security-relevant is output granularity. An API might return full per-token probabilities, only the top few candidates, a single sampled token, or just plain text. Each level of exposure changes what an observer can infer or optimize against: richer numerical output offers more signal, while text-only output offers less. The interface’s design, not just the model, sets this boundary.

Consequently, logits are a prerequisite for techniques that exploit observable output, including black-box functional model extraction, membership inference, model inversion and attribute inference, language-model training-data extraction, and partial parameter recovery from API behavior. They also feed sampling and decoding configuration. How much any exposure level actually enables is empirical and belongs to the cited sources.
