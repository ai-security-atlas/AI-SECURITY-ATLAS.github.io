Reasoning-token exhaustion and overthinking attacks

AI-generated draft · conceptual overview, not yet reviewed

Reasoning-token exhaustion and overthinking attacks craft inputs or retrieved context that force a reasoning model to spend excessive inference compute inside its internal deliberation phase. The objective is to degrade availability or increase cost by inflating hidden or intermediate token generation by an order of magnitude while keeping the visible prompt and final answer compact.

How it works

Models trained to emit test-time reasoning traces allocate variable numbers of thinking tokens depending on perceived problem complexity. An attacker — either directly through user input or indirectly through poisoned documents in a RAG system — embeds decoy reasoning puzzles, recursive verification branches, or ambiguous Markov decision traps. During decoding, the model enters protracted self-verification loops before producing its final answer. As a variant of token-cost and context exhaustion, this attack targets the internal test-time compute budget rather than prompt prefill length alone.

Exposure is highest on model-serving infrastructure where hidden reasoning tokens are billed or scheduled from the same GPU memory and slot pool as visible completions. Standard input-length caps do not stop the amplification because the trigger prompt itself can be short.

Defenses rely on explicit rate, token, cost and step budgets that cap reasoning-trace length separately from visible output tokens. Evaluation is framed through cost, latency and resource amplification; consult OverThink: Slowdown Attacks on Reasoning LLMs for empirical slowdown factors across reasoning architectures.
