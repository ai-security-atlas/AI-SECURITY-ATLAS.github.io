Least-privilege tools and scoped credentials

Limit reachable actions and data; approval must bind to actual arguments and destinations.

AI-generated draft · conceptual overview, not yet reviewed

Least-privilege tools and scoped credentials limit an agent to the narrowest set of actions and data it needs, so that the reachable attack surface is small and any approval binds to the actual arguments and destinations of a call. It concerns the tools, plugins, MCP and connectors an agent can invoke: each tool is granted only the permissions its function requires, and credentials are scoped rather than broad, ambient grants.

As a mitigation it is conditional and partial. It can reduce agent or connector confused-deputy abuse and exploitation of excessive delegated agency by shrinking what a hijacked agent is capable of doing, and it can blunt tool-output injection by ensuring that acting on injected content still cannot exceed the tool’s limited scope. It does not prevent abuse within granted scope: if a permitted action is itself damaging, or if approvals are bound to a tool name rather than to concrete arguments and targets, the constraint provides little protection.

Scoping trades some agent flexibility for a smaller blast radius, and it pairs with out-of-model authorization and human approval. Consult the cited authorization and agentic-application guidance for how scopes and approvals should be bound.
