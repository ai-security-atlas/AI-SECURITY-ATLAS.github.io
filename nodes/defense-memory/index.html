Memory provenance, review and expiry

Record who introduced persistent state and allow scoped review, revocation and reset.

AI-generated draft · conceptual overview, not yet reviewed

Memory provenance, review and expiry track who introduced each piece of an agent’s persistent state and make that state auditable, revocable, and resettable. It applies to persistent agent memory, where information retained across sessions can silently shape future behavior. The control records the origin and scope of memory entries and supports scoped review, selective revocation, expiry, and full reset, so that stored content is not treated as permanently trusted.

As a mitigation it is conditional. It can reduce the impact of persistent agent-memory poisoning by making injected or manipulated entries discoverable and removable, and by bounding how long any single entry persists before it must be re-earned. It does not prevent poisoning from occurring: malicious content can still be written to memory, and if provenance metadata is incomplete, review is infrequent, or a poisoned entry acts before it is caught, harm can precede detection. Expiry and review reduce dwell time rather than eliminating the exposure.

Because it addresses persistence specifically, this control complements action logging and authorization, which cover different phases of the same threat. The cited discussion of memory as an attack surface details the risks that provenance and expiry are meant to contain.
