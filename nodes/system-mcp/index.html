Model Context Protocol (MCP) and tool-server buses

MCPModel Context Protocoltool server bus

Protocol standardization unifies transport and schema discovery, not the trustworthiness of connected servers.

Standardized client-host-server protocol buses that connect models to external tools, resources, prompt templates, and sampling endpoints.

AI-generated draft · conceptual overview, not yet reviewed

The Model Context Protocol (MCP) and similar tool-server buses standardize how a host application connects a tool-using agent to external tools, plugins and connectors. Rather than wiring custom glue code for each integration, an MCP host discovers tools, resources, prompt templates, and sampling capabilities exposed by local (stdio) or remote (HTTP/SSE) servers over a shared JSON-RPC protocol.

Trust boundary

Standardizing the wire protocol unifies discovery and invocation, but it also concentrates multiple trust domains inside a single model context. In a typical session, the host aggregates tool definitions and resource metadata from several independent servers and presents them together to the model, while also handling reverse requests from servers back to the client (such as server-initiated sampling or dynamic capability updates).

Because descriptors, outputs, and protocol callbacks cross between distinct security principals, this component is the primary surface for tool-description poisoning, tool definition or behavior changes after approval, cross-server tool shadowing, and server-to-client sampling injection. Defending the bus requires per-server least-privilege tools and scoped credentials, explicit human approval for high-impact actions, and cryptographic pinning of tool schemas.
