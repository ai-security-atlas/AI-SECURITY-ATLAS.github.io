Direct prompt injection

Direct access does not imply control over privileged system messages.

Attacker-supplied instructions attempt to override application task or trust policy.

AI-generated draft · conceptual overview, not yet reviewed

Direct prompt injection is an attempt by an attacker who can address the model directly to supply instructions that override the application’s intended task or trust policy. It routes toward causing unauthorized actions or privilege use and violating intended behavioral constraints.

Conceptually the technique exploits context windows and in-context learning: because instructions and data share one context, attacker text placed there can compete with the application’s own directives. It also turns on trust boundaries and authorization. The attacker-controlled input is the injected instruction; the victim-controlled state is the system prompt, task framing, and any tools the application exposes. A load-bearing caveat is that direct access to the input does not imply control over privileged system messages — the attacker submits text, but does not thereby author the operator’s higher-trust instructions.

The important sibling distinction is with indirect prompt injection: there the malicious instruction arrives inside lower-trust content the system ingests, whereas here the attacker speaks to the model directly. Both live in the prompt-and-context-manipulation family and apply to language models and tool-using agents.

The candidate mitigation is to separate data from authority so that content in the context window is not automatically treated as a command; this reduces but does not eliminate the risk. Evaluation is framed through attack success and severity under an explicit threat model. For measured effectiveness against specific applications, defer to the cited sources.
